RELEASE_TAG = v1.0.3
RELEASE_DATE = 2026-09-05
RELEASE_BASE = 64ccc698c0a7628dccc5a3289a09e1faef88287a
RELEASE_STATUS = CANDIDATE_UNTIL_EXACT_HEAD_REVIEW_AND_TAG_PUBLICATION

## Purpose

Close the transition-chain conformance gap surfaced by the consumer adoption of
`v1.0.1`: the transition validator rejected a legal three-generation
whole-authority successor chain and raw historical frontmatter records, which
had allowed an executor to classify a failed raw full-graph transition as
non-blocking tooling debt. This patch makes the validator express the real,
unnormalized graph directly, so the raw gate can never need an exemption again.

## What this patch fixes

The `v1.0.1` validator supported exactly two generations: an accepted
predecessor and its proposed or accepted successor. A superseded middle
generation still carrying its own immutable historical `supersedes` edge was
rejected ("successor must be proposed or accepted"), and historical records
predating the current frontmatter schema failed array validation even when
frozen and unchanged. Consumers could not run the raw full-graph gate without
normalizing inputs.

`v1.0.3` accepts records raw and unnormalized and validates chains of any
legal depth:

```text
A accepted -> B superseded -> C accepted          (three generations)
A -> B -> C -> D (accepted)                       (four generations, and longer)
accepted predecessor + proposed successor          (preparation state, unchanged)
final accepted successor transaction               (atomic, unchanged)
```

Every supersession chain must terminate at exactly one accepted authority.
Cycles, chains terminating at a proposed successor, and superseded successors
newly activating an edge are rejected. All prior rejections are preserved:
premature predecessor retirement, premature backlinks, nonexistent
predecessors or successors, multiple successors, forked current authority,
mutation of accepted normative fields, partial supersession, and reactivation
of superseded authority. Missing `governed_by`/`supersedes` arrays are
tolerated only on `superseded` historical records; active records still
require well-formed arrays.

## Real-world regression fixture

The consumer chain that exposed the gap is vendored verbatim as a passing
regression fixture:
`AGENT_REPO_KNOWLEDGE_GOVERNANCE_V1` (superseded, raw minimal frontmatter)
-> `AGENT_DEVELOPMENT_GOVERNANCE_ADOPTION_V0` (superseded, reciprocal backlink)
-> `AGENT_DEVELOPMENT_GOVERNANCE_ADOPTION_V1` (accepted, current authority).

## Scope

This patch changes only the transition validator, its tests and fixtures,
version/release metadata, the changelog, and the deterministic manifest. It
does not change the accepted `AGENT_DEVELOPMENT_GOVERNANCE_V1` or
`AGENT_OPERATIONAL_LAYER_V1` Spec bytes, the protocol documents, or any
governance-route schema.

## Consumer impact

Consumers running the raw full-graph transition gate over historical
multi-generation graphs no longer need input normalization. No previously
accepted transition becomes invalid; the new checks strictly widen rejection
(cycles, proposed-chain terminations, superseded successors carrying new
edges). Consumers should re-vendor the exact annotated `v1.0.3` tag commit,
rerun repository-local verification, obtain independent review, and complete
their own Owner acceptance. `v1.0.0`, `v1.0.1`, and `v1.0.2` remain immutable
and MUST NOT be retagged or overwritten.

## Explicit non-effects

This release does not:

- accept or merge any consumer adoption;
- modify product code, runtime, production state, permissions, Grants,
  Credentials, Secrets, deployments, migrations, or GitHub settings;
- rewrite any consumer repository history, including records that predate the
  current frontmatter schema;
- move, overwrite, or retroactively relabel the `v1.0.0`, `v1.0.1`, or
  `v1.0.2` tags;
- change the accepted `AGENT_DEVELOPMENT_GOVERNANCE_V1` or
  `AGENT_OPERATIONAL_LAYER_V1` authority bytes.
