## What this patch fixes

Governance v1.0.0 correctly required preparation to remain distinct from local
Owner acceptance, but its transition validator treated every `supersedes` edge
as an already-active replacement. That rejected the legal preparation state:

```text
predecessor.status = accepted
predecessor.superseded_by = null
successor.status = proposed
successor.supersedes = [predecessor]
```

v1.0.1 recognizes that state as non-active, reviewable replacement intent.
Only the authorized final acceptance Head activates the edge atomically:

```text
predecessor.status = superseded
predecessor.superseded_by = successor
successor.status = accepted
successor.supersedes = [predecessor]
```

The validator still rejects premature predecessor retirement, premature
backlinks, nonexistent predecessors, non-strict successor IDs, partial
supersession, missing final backlinks, and mutation of accepted authority.

## Scope

This patch changes only distribution syntax documentation, schema description,
the transition validator, focused tests, version/release metadata, and the
deterministic manifest. It does not change the accepted
`AGENT_DEVELOPMENT_GOVERNANCE_V1` or `AGENT_OPERATIONAL_LAYER_V1` Spec bytes.

## Consumer impact

Consumers whose adoption upgrade is blocked by the v1.0.0 validator should keep
their current accepted adoption active, keep the new successor proposed, and
wait for a reviewed v1.0.1 release. They must then vendor the exact v1.0.1 tag
commit, rerun repository-local verification, obtain independent review, and
perform their own Owner acceptance. v1.0.0 remains immutable and MUST NOT be
retagged or overwritten.

## Explicit non-effects

This release does not:

- accept or merge any consumer adoption;
- modify product code, runtime, production state, permissions, Grants,
  Credentials, Secrets, deployments, migrations, or GitHub settings;
- implement `AGENT_OPERATIONAL_LAYER_V1`;
- move the v1.0.0 tag;
- claim deterministic validation is semantic review.

## Post-publication notice

The immutable `v1.0.1` tag contains the intended transition-validator fix, but
publication occurred without closing the required release-note finding that
`mayf3/svc-workflow` PR #22 had to be named explicitly, and the final tagged
Head did not receive a new recorded independent full patch-release review after
it changed from the previously reviewed candidate. Do not move or overwrite the
`v1.0.1` tag. New consumer adoptions should use a reviewed `v1.0.2` release.

## Publication gate

Before publication, an independent release review must bind the exact v1.0.1
candidate Head and verify the focused transition cases, complete repository
suite, manifest, version coherence, accepted-authority byte preservation, tag
absence, and consumer-local adoption boundary.
