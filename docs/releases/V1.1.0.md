## Purpose

Implement the accepted `AGENT_MODEL_CONVERGENCE_V1` distribution Contracts
(CTR-CONV-007, CTR-CONV-008) so that retirement of obsolete executable models
becomes part of the normal development grammar instead of a repeated repair
pattern that leaves permanent fallback paths behind. Acceptance of the Spec
(PR #16) authorized preparation only; this release candidate is the separate,
separately evidenced distribution-implementation stage.

## What this release adds

The accepted obligation enters the vendored surface as conditional guidance
in the existing workflow — no new subsystem, ledger, mandatory Agent role,
scoring service, approval workflow, or blocker class:

- `.agents/README.md` gains a self-contained model-convergence and retirement
  section: the affected-work trigger (historical IDs, duplicate models, old
  fields/configuration keys, old API/CLI entrypoints, legacy state stores,
  fallback paths, compatibility adapters, replacement dependencies, old
  runtimes/recovery paths), the duplication test (same business
  responsibility served by multiple independently maintained executable
  models), preserved distinct entities, the RETAIN / RETIRE / MIGRATE /
  TEMPORARY_BRIDGE dispositions, subtraction-first preference, the stable
  supported public facade versus temporary migration bridge boundary, and
  retirement without historical-evidence deletion.
- PREFLIGHT mode gains a conditional affected-work convergence probe with six
  bounded questions (alternatives, fact ownership, real consumers,
  migrate/delete/refactor preference, bridge consumer and exit condition,
  planned dispositions). Unrelated tasks skip the probe entirely: no global
  census, no empty matrix, no new approval.
- REVIEW mode gains a conditional convergence-exit review binding
  `NEW_PATH_USABLE`, `OLD_EXECUTION_PATH_RETIRED`, and
  `RECOVERY_DOES_NOT_REVIVE_OLD_PATH` to scope, revision, environment, and
  observation time; unknown coverage stays unknown; retirement is not
  historical-evidence deletion; review still uses the parent's existing
  blocker classes and legal sources.
- Change Brief and Review Record templates gain conditional convergence
  fields that are skipped when `MODEL_CONVERGENCE_APPLICABLE = NO`.

Two deterministic distribution-tool regressions are added: the vendored
surface must not reference source-only authority paths, and the convergence
surface must be present and conditional in the distributed files. Six
distribution canary decisions (legitimate distinct IDs, duplicate legacy
path, temporary bridge, stable facade, recovery revival, unrelated small fix)
are recorded under `docs/rationale/model-convergence/DISTRIBUTION_CANARIES.md`.

## Version class

MINOR (1.0.3 -> 1.1.0). This is the first entry of an accepted normative
obligation into the active distributed grammar — backward-compatible additive
guidance and template fields under `docs/releases/VERSIONING.md`, not an
editorial correction with semantic delta NONE. No grammar, protocol, format,
schema, or consumer-adoption change occurs; existing locks and vendor flows
remain valid, so MAJOR is not warranted and PATCH is unlawful.

## Scope

This candidate changes only the five distributed guidance/template surfaces
listed above, version and release metadata (`VERSION`, `CHANGELOG.md`,
source `README.md`, consumer lock template, manifest), the release document,
the implementation record, the canary record, and the distribution-tool
tests. It does not change any accepted Spec bytes, protocol documents,
schemas, or validators.

## Consumer impact

Consumers are unaffected until they separately adopt an exact revision of
this candidate through their own docs-only update PR, local review, and Owner
acceptance. The distributed guidance is conditional: tasks that never touch
historical alternatives keep their existing short route.

## Explicit non-effects

This release candidate does not:

- activate `AGENT_RELEASE_RECOVERY_ASSURANCE_V1`,
  `AGENT_REPOSITORY_QUALITY_V1` (PR #17), or GitHub-enforcement proposals;
- promote the non-normative `docs/guides/EVIDENCE_LED_REFACTORING.md` guide
  to a Contract, blocker, or distributed MUST;
- accept or merge any consumer adoption, or modify any consumer repository,
  product code, runtime, production state, permissions, Grants, Credentials,
  Secrets, deployments, migrations, or GitHub settings;
- tag, publish a GitHub Release, or move any prior immutable tag;
- change the accepted `AGENT_DEVELOPMENT_GOVERNANCE_V1` or
  `AGENT_MODEL_CONVERGENCE_V1` authority bytes;
- authorize production cleanup, identity merges, or destructive migrations
  anywhere; convergence execution remains separately authorized per product.
