## What this release contains

This is the first stable reusable distribution of the accepted Agent Development Governance V1. It separates three independent decisions:

```text
new or changed long-lived obligation -> Authority action
execution complexity                 -> Plan level
failure consequence                  -> Assurance level
```

The release includes:

- Product Authority versus one-operation Execution Mandate;
- `REUSE | AMEND | SUPERSEDE | NEW` authority routing;
- `NONE | BRIEF | EXEC_PLAN` planning levels;
- `ROUTINE | DURABLE | CONTROLLED` assurance levels;
- Change Brief, ExecPlan, Execution Mandate, Controlled Runbook, Review, and Conformance templates;
- load-bearing `SPEC_GAP`, Evidence reviewability, live-authority-gap, emergency-containment, exact-Head/Base, and stop controls;
- deterministic route-consistency and authority-transition validators;
- four complete historical failure regressions and three route-distinct canaries;
- exact-commit vendoring with consumer-local acceptance.

## Adoption

A consumer must vendor the exact published tag commit, create its own proposed adoption record, perform repository-local review, and activate the adoption only through its own authority branch. Do not bulk-rewrite consumers or historical work.

## Explicit non-goals

This release does not:

- implement `AGENT_OPERATIONAL_LAYER_V1`;
- change any consumer repository;
- modify product code, runtime, production state, permissions, Grants, Credentials, Secrets, deployments, migrations, or GitHub settings;
- introduce a GitHub App, WebAuthn ceremony, merge broker, WORM store, central registry, or fixed Agent formation;
- claim that deterministic validators perform semantic review.

## Publication sequence

After the release-candidate PR receives independent exact-Head full release review, an authorized maintainer may atomically:

1. recheck Base, Head, tests, review, and tag absence;
2. mark the PR Ready;
3. create the immutable `v1.0.0` tag on the exact reviewed release Head;
4. create the GitHub Release from these notes;
5. merge the exact reviewed Head without changing its tree;
6. verify tag target, merge parents/tree, and release metadata.

Consumer adoption is a separate later task.
