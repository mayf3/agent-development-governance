# 证据驱动的简化与重构

状态：**非权威实操参考**。这是对 DeepSeek Harness 与 Hermes 方法的本地提炼，不是新 governing Spec、自动调用的 Skill 或新的合并门槛。来源编号见 [来源与取舍](../rationale/deepseek-hermes/SOURCE_REVIEW.md)，边界案例见 [作者案例](../rationale/deepseek-hermes/SCENARIO_REVIEW.md)。

目标是减少需要独立维护的概念、入口、状态和解释，而不是追求删行比例、候选数量或并行 Agent 数量。先证明哪些复杂性没有必要，再在已授权范围内小批改变，最后验证实际整合结果。

## 1. 使用范围与现有权威

适合明确请求的简化调查、已授权重构、重复故障的结构分析，以及多分支变更的整合。普通无关任务不自动附加一次全仓清扫。小任务可以由一个 Agent 顺序检查不同视角；同一作者切换视角不构成独立审查。

开始前读取目标仓库的治理入口，用既有 [PREFLIGHT](../../.agents/skills/spec-governance/modes/PREFLIGHT.md) 区分 authority、plan 和 assurance。调查授权只允许调查；本指南不会让外部 Skill 的“安全修改可自动应用”成为写入许可。已有授权充分时也不额外制造一轮确认。

本地约束的来源是 [Governance V1](../specs/AGENT_DEVELOPMENT_GOVERNANCE_V1.md)、[Model Convergence V1](../specs/AGENT_MODEL_CONVERGENCE_V1.md) 与适用的 [Operational Layer V1](../specs/AGENT_OPERATIONAL_LAYER_V1.md)。它们分别拥有授权与证据、旧路径退出、Skill/Record 非权威边界。本指南不改变这些规则，也不改变 Operational Layer 的历史父规范。

这里给出的试点、清单和检查方法是可选执行建议。只有既有有效 Contract、机器门槛或有效任务授权能按现行 REVIEW 规则产生阻断依据；Reviewer 不能把某条外部建议现场提升为义务。涉及新长期语义时返回现有 authority 路由。

## 2. 调查：先形成少量强候选

### 2.1 找真实消费者，不把搜索结果当最终证明

从目标功能与必要依赖开始，查看生产入口、公开接口、配置、插件注册、字符串事件、动态导入、构建产物、历史迁移与恢复路径。将消费者分成生产、非生产、用途尚不明确三类；示例和脚本可能是实际 smoke 入口，不能仅按目录判断。

静态工具和文本搜索用于发现线索。仓内没有调用者，不等于没有仓外插件或受支持消费者；测试是唯一调用者，也不等于该测试没有价值。先定位产品承诺、原设计原因及现实调用路径，再决定删除、迁移、保留或继续调查。（D1、H1、H3）

对于每个候选，说明至少一个真实成本：重复状态需要协调、一个公共方法暴露无用能力、历史适配层使发布多维护一套解释，或手写基础设施使专用测试与文档长期增长。无法指出成本的格式偏好不升级为重构任务。

### 2.2 四个观察视角，不是四个固定岗位

| 视角 | 要寻找的问题 | 不能误删的东西 |
|---|---|---|
| 复用 | 是否已有同职责实现；新 helper 是否只是换了名字 | 职责、授权或失败语义不同的实现 |
| 简化 | 重复状态、无消费者能力、参数堆积、无必要的转发层 | 真实扩展接口、兼容承诺、并发与持久化边界 |
| 效率 | 重复读取、无界缓存、资源泄漏、隐式串行 | 有顺序要求的操作和必要审计事实 |
| 修复层次（altitude） | 是否只修一个调用点，其他调用点仍有同一根因 | 有意的隔离层、分阶段迁移和供应商边界 |

这是对 Hermes 视角的适配，不采纳其固定四 Agent 或风险标签自动授权。需要修改共享机制才能解决的问题可以单独提出，但“更深的修复”不授权在局部清理中重建平台。（H3）

### 2.3 先尝试推翻候选

找到当初为什么保留它：当前权威、调用者、历史提交、事故记录和必要的反例。向另一检查者提供候选、坐标与源材料，让其寻找反证，而不是只提供作者的论证。共识数量不是证明；一个真实消费者就可能推翻“死代码”判断。（D1、H4）

把重要候选归为保留、实施候选、缺证据或超范围，并记录代表性的驳回原因。同机制的多个建议合并到已有知识记录；不为了凑数新建文件。小的局部清理可以留在现有 PR 说明中。

### 2.4 衡量净维护变化

考虑实现、专用测试、文档、配置、发布与兼容成本，而非净删行数。用内建能力或维护良好的依赖替代手写实现时，同时检查版本下限、语义缺口、许可与供应链要求、传递依赖及剩余适配层。只是把同样复杂性搬进 wrapper，不算明确收益。（D1）

将当前需求与假想需求分开。DeepSeek 的 pre-stable API 立场不能转移为本地仓库随意删除接口、历史数据或安全约束的许可。格式升级、支持承诺和身份关系继续由产品拥有者决定。

## 3. 实施：先固定哪些语义不能变

行为保持型重构的起点是明确的受影响行为清单，例如公共导出、配置默认值、错误与取消、资源所有权、授权拒绝、持久化/线协议，以及模型实际看到的 prompt、tool schema 和输出。并非所有内部细节都必须保持字节相同；哪些内容要求字节一致，由拥有该承诺的 Contract 决定。（D2、H1）

对机械替换先选有代表性的小样本，包含会推翻替换假设的输入。例如合并条件分支要检查匹配优先级，提取 helper 要检查异常传播和清理时序。修正假设后再扩大，不能用批量改写加刷新 expected outputs 制造全绿。

测试说明当前实现，但不会自行赋予产品权威。确实只保护退役行为的测试可以随合法退役处置；对应的消费者退出与负向证明仍需保留。不能因为测试失败就删测试，也不能因为测试存在就永远保留多余实现。（D1、D2）

抽取大文件按职责而不是行数切块；共享 helper 指定一个整合拥有者。确有外部兼容义务时，薄 facade 可以暂时存在，但内部调用逐步指向当前拥有者，并按 Model Convergence 的实际退出条件处置桥接。不要把 facade 再做成一套状态权威。（H1）

特别检查源码运行与安装产物：移动模块后，包的包含规则、导出、插件装载或生成清单可能未同步。公共符号的静态差异检查能发现遗漏，但不能覆盖所有动态调用或证明接口行为正确；补充实际装载和适用的行为验证。（H1、H2、D7）

## 4. 并行：放大独立工作，不放大未验证假设

大范围工作先用脚本完成确定性的目录枚举、依赖扫描和结果汇总，再把需要判断的独立单元交给 Agent。先做一个小范围试点，记录资源、上下文、耗时及实际收益，再决定是否扩大；没有适用工具时报告限制，不伪装已经派发。（H4）

建议每个 worker 使用隔离工作树或等价隔离写入面，固定基线和独占路径；共享文件交整合者处理。不要照搬外部流程中共享索引、按行分割同一文件的方式。任务说明至少包含：共同目标与不变量、允许写入范围、不得改变的行为、检查入口、交付物与停止条件。

并发数、嵌套深度、总资源预算由实际环境和授权决定，不采用 1,393、4 或 12–16 这样的通用常数。独立工作树不会隔离端口、账号限流、数据库、测试 runner 或宿主进程；这些共享资源另行限定。（D3、H4）

worker 的交付以精确提交与可检查结果为依据，不只看 `completed`、摘要或创建文件数。摘要截断、通知先到、子任务失联或存在未提交尾部时，先核对当前任务身份、存活和已提交产物；不能直接重派可能仍在产生副作用的任务。（H2、H4）

每轮整合先让 worker 停写并确认最终 HEAD，再读取它们的实际 diff、范围、检查和未完成项。整合提交要能对账每个已交付变更；普通 merge 可以核对祖先关系，squash/cherry-pick 则用对应映射与内容检查，不能机械套用“零未合并提交”。整合后再发现 worker 新提交，就重开这一项的收口，而不是继续称本轮完整。

冲突由双方意图、当前 Contract 和明确拥有者解决，不盲选 ours/theirs，也不把“main 永远正确”当产品规则。最终对合并后的文件树做适用集成验证，不能相加各分支 PASS。当基线变化时，先检查实际相关影响；不自动全量重审。（H4；本地 Governance V1）

## 5. 验证：观察真实边界，而不是实现自己的回声

对跨组件不变量，优先比较能够独立出错的观察，例如生产者发出的事件与读取者重建的历史。同一 helper 算出 actual 和 expected 不足以独立证明其正确。检查组件存在或返回值形状仍可用作装载/接口测试，只是不应被冒称为更强的不变量证明；安全校验也不能因看似重复就删除。（D1、D2）

选择检查时把“运行哪些测试”和“覆盖哪些受影响源文件”分开。动态注册、配置、进程和发布产物常常不在静态依赖图里。局部变更用有针对性的证据；真正跨组件的整合采用足以覆盖组合影响的检查。保持目标仓库已有的更严格门槛，不移植 DeepSeek 的特定命令或覆盖率常数。（D7）

资源与并发相关测试可按以下顺序审视：（D3）

- 由资源分配者原子分配端口、临时目录或命名空间，而不是先探测空闲再占用。
- 取得资源后立即注册清理；恢复环境变量时区分原来不存在与原来有值。
- 用事件、屏障或状态证明 readiness 和重叠，而不是固定睡眠。
- 关闭、取消或 kill 后等待对应完成信号，证明没有跨测试的尾部副作用。
- 用负向样本或修复前失败证明回归测试确实能发现目标问题；随机压力运行只作补充。

不要用放宽断言、吞错、无原因重试或全局串行掩盖 fixture 缺陷。有据可查的外部瞬时故障重试、平台限定或超时预算恢复应明确原因与范围，不将跳过项报告为通过。

红灯在相同环境的精确基线与候选上对照：同样失败可支持“未由本次引入”，不能自动支持“本次所有要求已满足”。环境不具备、范围未覆盖、门槛未通过分别报告；保持秘密值不进入证据。（H1、H4；本地 Governance V1）

## 6. 文档与上下文：少读无关内容，不少读必要约束

压缩说明前逐项保留主体、动作、条件、时序、强制/允许程度、例外、失败后果和所有权。删掉复述代码的旁白，保留会防止误删或误用的 WHY。prompt、错误消息等可见文字可能就是行为，不按纯格式改写处理。（D4）

当前使用说明、设计理由、历史调查和审查证据各有自己的用途。更新可维护的说明源，再生成网站或其他派生内容；必要局部契约仍可在使用点重复。归档依据未来决策价值，不按年龄、长度或删除配额自动处置；本地 accepted Spec 与不可变证明继续遵循现有保留/替代规则，不复制 DeepSeek 的 Note 生命周期。（D5、D6）

根入口保留通用安全与导航，域内细节按任务加载，检查目录指引实际可达且没有被静默截断。短上下文不是独立目标：移除无关材料后，还要确认执行者能取得适用约束。不要为省 token 固定降低所有 worker 的上下文上限。（H1、H2）

## 7. 用实际收益收口

可以对比维护入口数、独立状态数、受影响模块、定位一个实际符号需要读取的无关内容、构建/装载与适用运行成本。同时报告模块数、依赖边和启动成本可能增加的代价。采用相同任务样本和基线，区分静态指标、检索模拟、执行测试和真实用户效果。（H1、H2）

没有测量就写未测量；供应商的估算成本不是发票，模拟节省不是实测节省，不把不同人群或时间窗的数字相加。符合已授权范围的任务可以先结束，整仓质量、分发启用和生产完成则不能据此宣布。

旧模型清理仍使用 Model Convergence 的“新可用、旧退出、适用恢复不复活”。调查没有发现合格候选也是有效结果；达到既有 Done When 后停止，不自动开启下一轮扫描。

## 8. 可粘贴到已有 Brief 的最小记录

下面是可选内容，不要求每个小任务建表或新增 Record。已有内容可直接链接。

```text
候选：具体对象及 exact revision / file:line。
消费者：生产、测试文档、外部/动态使用与未知范围。
为何保留：原始目的、最强反对理由及查到的反证。
简化收益：退掉什么维护面，增加什么依赖或适配成本。
行为与权限：哪些不变；哪些需要既有 authority 路由；本次写入边界。
验证与退出：反例、组合验证、旧路径退出；未运行和未覆盖项。
结论：保留 / 实施候选 / 缺证据 / 超范围，以及停止点。
```

并行交付时，在现有任务记录追加实际使用的工作树、基线、允许路径、最终提交、证据位置与未完成项即可。整合者的收口记录绑定最终整合提交和交付完整性，不依赖聊天摘要作为唯一证据。

## 9. 本次集成到哪里

本次仅添加可导航的参考指南、固定版本的来源对照与作者案例，不修改 `.agents/**`、distribution、CI 或 governing Spec。它不是 Operational Layer 全量实施，也不是 Model Convergence 分发接入完成。

今后将某段建议变成自动选择的 Skill 或强制检查时，先与既有任务入口去重，再按现有权威和分发采用程序处理。无需为已接受规则再创一份同义标准；确实新增的长期义务也不能躲在“指南”里直接生效。
